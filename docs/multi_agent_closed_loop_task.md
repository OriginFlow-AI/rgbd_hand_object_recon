# 多智能体协同闭环任务协议

这份协议用于让任务从“边做边问”切换为“一次性交付”。用户只给目标、边界和验收标准；执行方自主完成分析、实现、测试、文档、打包、提交和上传。

## 1. 用户指令模板

```text
目标：
在 <仓库/模块> 内完成 <具体目标>。

范围：
必须包含 <code/doc/test/report/package/commit/push>。
不要处理 <明确排除项>。

验收：
必须跑 <命令/测试/脚本>。
必须产出 <文件路径/报告/截图/视频/指标>。
关键指标达到 <阈值或结论>。

协同：
需要时启用多智能体并行，主智能体负责整合和最终质量。

沟通：
不要逐步汇报过程；除非遇到破坏性操作、权限缺失、需求冲突或无法自主判断的高风险选择，否则一直执行到闭环。

最终输出：
只给 key result：提交号、上传位置、交付物、指标、技术结论、剩余风险。
```

## 2. 最短可用版本

```text
请在当前仓库一次性闭环完成 <任务>：自主分析、实现、测试、文档、打包、提交并 push。需要时启用多智能体协同。不要过程汇报，最终只输出 commit、产物路径、指标和技术结论。
```

## 3. 多智能体协同分工

| 角色 | 职责 | 交付 |
|---|---|---|
| 主智能体 | 拆解任务、控制范围、整合变更、最终验收、提交上传 | 最终 commit、KR 摘要 |
| 实现智能体 | 负责独立代码模块或脚本，不改其他范围 | 代码 patch、文件清单 |
| 文档智能体 | 负责说明、模板、交付规范，不改代码逻辑 | doc patch、可复用模板 |
| 验证智能体 | 独立跑测试、检查输出、找遗漏和冗余 | 验证报告、风险清单 |
| 评审智能体 | 从用户验收视角检查是否闭环 | 是否可交付、缺口 |

对于本工程的表面重建，推荐按真实失败边界划分：架构/契约、表面融合、质量/可视化和
主集成。运行时几何程序必须保持确定性，不在重建链中调用 LLM 智能体。

并行原则：

- 写入范围必须互不重叠。
- 主智能体不等待非关键路径结果才开始工作。
- 子智能体输出必须被主智能体复核后才能进入最终提交。
- 发现冲突时以验收标准和最小变更为准。
- 先冻结 `domain.py` 与 `manifest.json`，其他角色只通过稳定契约交接。
- 交付必须报告接口假设、验证命令、关键数值和剩余风险。

## 4. 闭环停止条件

任务只有同时满足以下条件才算闭环：

- 代码、文档、测试或报告已落到具体文件。
- 验收命令已实际运行，并记录关键结果。
- 生成物路径明确，可复现。
- 技术结论写清能力边界和剩余风险。
- 需要提交时，commit 已完成；需要上传时，push 已完成。
- 工作区没有意外未提交源码变更。

## 5. 去冗余输出格式

最终回复只保留：

```text
完成：
- commit：
- 上传：
- 交付物：
- 验收指标：
- 技术结论：
- 剩余风险：
```

不要输出：

- 过程流水账。
- “我正在/我准备/我已经看了”。
- 没有文件路径或数值的完成描述。
- 重复粘贴长日志。

## 6. HTML 协同校验报告

当前仓库提供一个可复现的多智能体协同校验 HTML 报告生成器：

```bash
bash scripts/run_multi_agent_validation_report.sh
```

输出：

```text
outputs/reports/multi_agent_validation_report.html
outputs/reports/multi_agent_validation_report.json
```

报告内置五组规则化校验视角：

- 代码与接口智能体。
- Schema 智能体。
- 测试与产物智能体。
- 文档与周报智能体。
- 验收视角智能体。

它是验证矩阵，不等于真实并行智能体执行记录；用于周报和验收展示，不替代真实系统
接入后的人工复核和真实数据精度评测。
